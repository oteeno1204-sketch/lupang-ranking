# 루팡 v5.0 — 길드 생명주기와 APK 전체 투력 갱신 배포

## 포함 기능

- 최고관리자가 프로필 ID 없이 비활성 길드를 만들고, 일회용 4자리 최초 길드장 코드를 발급합니다.
- 최초 길드장이 코드로 가입하면 길드장 지정과 길드 활성화가 한 트랜잭션으로 처리됩니다.
- 최고관리자는 길드를 비활성화·복구하고, 비활성 길드만 이름 재확인 후 영구 삭제할 수 있습니다.
- APK의 현재 길드장·관리자는 공식 조회를 허용한 대표 캐릭터 전체를 한 명씩 순차 갱신할 수 있습니다.
- PWA에는 전체 갱신 버튼과 네이티브 WebView 조회가 노출되지 않습니다.

## 배포 전 확인

운영 DB 백업을 먼저 만들고 아래 명령을 실행합니다.

```bash
npm ci
npm test
npm run test:v50
npm run typecheck
npm run build:web
```

`GUILD_INVITE_HASH_SECRET`은 기존 운영값을 유지해야 합니다. 값을 바꾸면 이미 발급된 4자리 초대코드를 검증할 수 없습니다.

## 배포 순서

아래 순서를 바꾸지 않습니다. 새 Edge Function이 새 RPC를 호출하므로 DB가 먼저 준비돼야 합니다.

### 1. DB 마이그레이션

적용 대상:

- `20260828075403_v50_owner_invite_role.sql`
- `20260828075416_v50_guild_owner_claim_lifecycle.sql`

```bash
npx supabase@latest link --project-ref cqvwdehrsycjjuluxmxr
npx supabase@latest db push --dry-run
npx supabase@latest db push
```

첫 마이그레이션은 `guild_invite_role.owner` enum 값을 먼저 커밋하고, 다음 마이그레이션이 해당 값을 사용하는 RPC를 생성합니다.

### 2. Edge Function

```bash
npx supabase@latest functions deploy api --project-ref cqvwdehrsycjjuluxmxr --no-verify-jwt
```

### 3. PWA와 APK

PWA는 일반 길드 관리·가입·최고관리자 화면 변경을 반영하기 위해 다시 배포합니다. 전체 투력 갱신은 웹에서 렌더링되지 않습니다.

APK에는 네이티브 WebView 순차 갱신 조정기가 포함되므로 새 APK 또는 호환되는 EAS Update를 배포합니다.

```bash
npm run build:web
npm run build:apk
```

## 운영 확인 순서

1. 최고관리자 계정으로 새 길드를 만듭니다.
2. 새 길드가 `inactive`, 길드장 미지정 상태이며 4자리 `최초 길드장 초대코드`가 표시되는지 확인합니다.
3. 길드가 없는 테스트 계정이 해당 코드로 가입합니다.
4. 가입 즉시 해당 계정이 `owner`, 길드가 `active`, 코드는 재사용 불가인지 확인합니다.
5. member/admin 코드 발급과 기존 가입이 그대로 동작하는지 확인합니다.
6. 최고관리자가 테스트 길드명을 정확히 입력해 비활성화하고, 기존 콘텐츠가 보존되는지 확인합니다.
7. 복구 후 owner와 가입 가능한 멤버십이 정상 활성화되는지 확인합니다.
8. 별도 테스트 길드를 비활성화한 뒤 영구 삭제하고 `platform_audit_logs`에 대상 ID·이름·항목별 개수가 남는지 확인합니다.
9. APK에서 owner/admin 계정으로 `투력 관리 → 길드원 전투력 전체 갱신`을 실행합니다.
10. 성공·실패·미등록이 캐릭터별로 집계되고 한 명의 실패 뒤에도 다음 캐릭터가 처리되는지 확인합니다.
11. 일반 길드원과 PWA에서는 전체 갱신 버튼이 보이지 않는지 확인합니다.

## 안전 규칙

- `owner` 코드는 평문으로 DB에 저장되지 않고, 최고관리자만 미지정 비활성 길드에 1회용으로 발급할 수 있습니다.
- 길드 비활성화와 영구 삭제는 입력한 길드명이 서버의 현재 길드명과 정확히 같아야 합니다.
- 영구 삭제는 비활성 길드만 가능하며 되돌릴 수 없습니다. 실제 운영 길드에는 먼저 비활성화와 복구를 검증합니다.
- 삭제 감사 기록은 길드 외래키 없이 보존되지만 삭제된 게시물·앨범·채팅 본문을 복사하지 않습니다.
- 전체 투력 갱신 중 앱을 닫거나 다른 화면으로 이동하면 작업이 중단됩니다. 다시 시작해도 공식 일자별 저장 규칙에 따라 중복 기록이 방지됩니다.

## 롤백

- 앱 또는 Edge Function에 문제가 있으면 이전 배포 버전으로 되돌립니다.
- DB enum 값과 이미 생성된 감사 로그 테이블은 제거하지 않습니다.
- 새 길드 생성과 owner 코드 발급을 일시 중단한 뒤, 이미 생성된 비활성 미지정 길드는 수정 버전 배포 후 새 owner 코드를 다시 발급합니다.
- 영구 삭제된 길드는 애플리케이션 롤백으로 복구되지 않으므로 운영 백업에서만 복원할 수 있습니다.
